Devolved administrations, local government and the NHS

Audit and progress reports outside Whitehall describe legacy by contract and system, rarely by programming language. That gap is itself a finding: the technology behind these services is mostly not published.

Who runs the legacy estate

Much legacy code is maintained by private suppliers working on government's behalf. Long single-supplier arrangements are part of the debt.

Beyond central government

Skills and talent

Who can still maintain it

No UK government dataset counts staff by programming language. What follows is the best available evidence: audit findings, live job adverts and industry surveys. Read the surveys as indicators, not a census.

Do skills shortages cause technical debt?

The evidence shows the two reinforce each other. A shortage makes change slower and dearer, so systems are left alone, so the code grows older and the pool shrinks further.

An age-inclusive approach to legacy skills

Retirement is a real risk to legacy knowledge. It is a planning fact about the workforce, not a judgement about any group of people, and the response must stay fair to people of every age.

Skills needed to refactor or replace legacy code

Moving off a legacy language takes two skill sets working together: people who can read the old system, and people who can build and run the new one. Role names follow the Government Digital and Data Profession Capability Framework. Analysis

Migration and decommissioning

How legacy code is moved

The umbrella term is application modernisation. Moving code from one language to another is code conversion or translation. Suppliers on the government's G-Cloud framework describe six routes, known as the 6 Rs.
